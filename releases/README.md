# Release notes

Notes for the upcoming release are written manually to `releases/release.md`. Add to this file along with the
changes worth mentioning, it has to be merged to the default branch before the Release workflow is started.

The Release workflow (`.github/workflows/release.yml`):

1. publishes the content of `releases/release.md` as is as the GitHub Release description;
2. renames the file to `releases/<version>.md`, e.g. `releases/3.0.0.md`;
3. creates an empty `releases/release.md` for the next release;
4. commits both files together with the version bump.

When `releases/release.md` is empty:

- major release cannot be made, the workflow fails before anything is published;
- minor and patch releases get notes generated by GitHub from merged pull requests (see `.github/release.yml`),
  no `releases/<version>.md` is created.
