## Breaking changes

### `clientURL` is not supported anymore

Server used to navigate the headless browser to the `clientURL` sent by the client before loading the exported HTML.
That allowed a client to make the server open any URL. The field is now ignored: requests which still send it keep
working, but the server never navigates to it.

Exported HTML is now kept in memory and served to the headless browser from a local address generated by the server,
like `http://127.0.0.1:53124/8a6e0f6c-0d1b-4c64-9d56-0c2e3f6a1b7e`. The address only exists while the page is being
exported and is not accessible from outside the machine (or the Docker container) the server runs on.

If you relied on `clientURL` to load styles and fonts, do one of the following:

- send `Access-Control-Allow-Origin: *` header for the resources from your web server;
- start the export server with a specific `--page-port` and allow that origin only, e.g.
  `Access-Control-Allow-Origin: http://127.0.0.1:8090`;
- host the resources on the export server (`--resources`).

See [architecture](https://github.com/bryntum/pdf-export-server/blob/main/docs/architecture.md) and
[configuration](https://github.com/bryntum/pdf-export-server/blob/main/docs/configuration.md) guides for details.

### Node.js 24 is required

Minimum supported Node.js version is 24. The server is tested on Node.js 24 and 26.

## New

- `page-port` config (`--page-port` on the command line) sets the port of the local address used to pass exported
  pages to the headless browser. A random free port is used when it is not set.

## Other changes

- `muhammara` package is replaced with its successor `@muhammara/native`, which supports Node.js 26.
- Docker image uses npm 12 with `glob`, `minimatch` and `@sigstore/verify` updated to the versions without known
  vulnerabilities.
